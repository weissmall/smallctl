# Contributing

This project follows [Conventional Commits](https://www.conventionalcommits.org/).

## Commit message format

```
<type>: <short description>
```

- Use one of the common types: `feat:`, `fix:`, `docs:`, `refactor:`,
  `test:`, `chore:`, `style:`, `perf:`, `build:`, `ci:`
- The description must be **short but descriptive** — lowercase, no trailing
  period, imperative mood.
- Use the commit body only when the subject alone is insufficient.

## Instructions for AI agents

1. Write commit messages yourself; never include "Generated by", "Co-authored-by",
   or similar tool attribution lines.
2. Pick the type that matches the change:
   - new functionality → `feat:`
   - bug fix → `fix:`
   - documentation only → `docs:`
   - test-only changes → `test:`
   - no behavior change → `refactor:`, `style:`, `chore:`, etc.
3. Keep the subject under ~50 characters when possible, e.g.:
   - `feat: add --no-wait flag to invoke`
   - `fix: remove stale socket on startup`
   - `docs: add qna document`
4. One logical change per commit. If a change spans multiple types, split it.
5. Never commit secrets or generated binaries.
